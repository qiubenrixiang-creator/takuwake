# 卓分けの館

ボードゲーム会の席決めを、診断クイズで行うツールです。
参加者がスマホで質問に答えると、遊びたいゲームの傾向が近い人同士が同じ卓に集まります。

隠しルート・図鑑・称号・エンディングを含んだ、遊べる作りになっています。

- 公開URL: https://takuwake.vercel.app/
- 制作: HINATA AKIMOTO

プログラムに触れずに中身を書き換えられます。

## 使い始めるまで

### 1. Firebaseのルールを設定する

名簿は Firebase Realtime Database に保存されます。
`js/firebase-config.js` の `apiKey` は公開されても問題ない種類のキーですが、
**データを守っているのはルールの方**なので、必ず設定してください。

1. https://console.firebase.google.com/ → プロジェクト `takuwake-no-yakata`
2. 構築 → Realtime Database → 「ルール」タブ
3. `docs/firebase-rules.json` の中身を貼り付けて「公開」

このルールでは、`roster`（名簿）と `config`（幹事が共有する人数）への
書き込みだけを許可し、それ以外の場所は禁止しています。

**今回、次の項目を追加しました。ルールを更新しないと弾かれます。**

- 名簿に `exp`（腕前）と `leave`（途中退出）
- `config` に `holdResults` `revealed` `revealedAt`（待機モード用）

貼り替えないと、名簿への登録そのものが失敗します。必ず先に済ませてください。

なお `config` を追加したのは、後述の「人数の共有」機能のためです。
ここを設定しないと共有ボタンだけが動かず、他の機能は今まで通り動きます。

### 2. Vercelにデプロイする

GitHubリポジトリと連携すれば、push するたびに自動で反映されます。
ビルド設定は不要です（Framework Preset は Other、そのまま Deploy）。

## 卓組みの間（幹事用ページ）

館の中にある、幹事だけが入れる部屋です。入口は2つあります。

- **名前の入力欄に `たくぐみ` と入力する**
- **神の座から「『卓組みの間』へ渡る」を選ぶ**

URLを直接開いても扉に錠がかかっていて、合言葉を求められます。
参加者にはこの合言葉を教えないでください。

合言葉は `js/kumi.js` の先頭にある `KUMI_PASSWORD` で変えられます。

診断を終えた全員を、まとめて卓に割り当てます。館の診断は「診断した順に
空いている卓へ入れる」方式なので、後から診断した人ほど希望と違う卓に
回りがちでした。この画面は全員そろってから一度に計算するので、
順番による有利不利がありません。

### 何を基準に組んでいるか

**揃える軸**は、会話量・テンポ・ゲームの重さの3つです。
静かに考えたい人とわいわい喋りたい人が同席すると、どちらも楽しめません。

**散らす軸**は、運まかせか戦略かの好みです。ここは違っていても問題に
ならず、むしろ違う方が面白いので、あえて計算に入れていません。
卓の紹介文に使うだけです。

そのうえで、次の2つを強い条件として扱います。

- 初心者だけの卓を作らない（ルール説明ができる人を各卓に散らす）
- 途中で帰る人を、重量級の卓に入れない

この2つのために、診断の直前で腕前と途中退出の予定を聞いています。
クイズの分岐からは分からないのに、当日いちばん効く情報だからです。

### 待機モード

会が始まる前に「結果を伏せる（待機モード）」を押しておくと、
診断を終えた人の画面には卓が出ず、ぬしが「しばし待つのじゃ」と伝えます。
記録画面でも、卓の中身は伏せられます。

幹事が「全員に席を告げる」を押した瞬間、待っていた全員の画面に
一斉にファンファーレとともに席が映し出されます。
画面を開いたまま待っていれば、操作は要りません。

伏せずに使えば、今までどおり診断した時点で仮の卓が出ます。
どちらで運用するかは当日決められます。

### 使い方

1. 会の前に「結果を伏せる（待機モード）」を押す（任意）
2. 全員の診断が終わったら「卓を組む」
3. 気になるところは名前をタップして入れ替える（2人選ぶと交換）
4. 動かしたくない人は「固定」しておくと、組み直しても動きません
5. 「全員に席を告げる」で、待っている全員に一斉公開されます
6. 「卓に置く札を印刷する」で、1卓1枚の紙が出せます

席を書き込んでから公開の合図を出す順にしてあります。逆にすると、
席が空のまま公開されてしまう人が出るためです。

計算結果はあくまで下書きです。当日は遅刻・欠席・相性など必ず想定外が
起きるので、手で直せる余地を残してあります。

## 当日の流れ

1. 幹事が参加人数を入力し、「この人数を全員に共有する（幹事用）」を押す
2. 参加者はURLを開いて診断する（人数は自動で入っている）
3. 「📜 記録」で、誰がどの卓かをリアルタイムに確認できる
4. 会の終了後、幹事が「🗑️ 来訪者の記録をリセット」で名簿を空にする

リセットは誤操作を防ぐため、「りせっと」と入力する確認を挟みます。

## 今回の変更点

### 直した不具合

**同じ名前の人が上書きされていた**
名簿のキーに名前を使っていたため、「ひなた」が2人いると
先に診断した人の記録が消えていました。端末ごとに発行するIDをキーに変更しました。

**リセットが失敗しても成功と表示されていた**
`db.ref('roster').remove()` の結果を見ずに「リセットしました」と出していたため、
権限エラーで消えていなくても気づけませんでした。成功・失敗を出し分けるようにしました。

**名簿への登録が失敗しても気づけなかった**
通信が切れた状態で診断を終えると、無言で登録されないままでした。
失敗時に画面上部へ通知を出します。

### 使いやすくした点

**文字送りをスキップできる**
メッセージ欄をタップすると残りが一気に表示されます。
1文字45ミリ秒なので、長いセリフは10秒近くかかっていました。
参加者が順番待ちしている場面では、ここが一番の詰まりどころだったはずです。

**幹事が人数を共有できる**
これまでは全員が同じ人数を手入力する必要があり、
ひとりでも違う数字を入れると卓数が食い違っていました。
幹事が一度共有すれば、他の端末に自動で反映されます。

**Enterキーで進める**
人数・名前・深淵の解答欄で、Enterでも決定できます。
スマホのキーボードでも決定キーが出るようにしました。

**人数入力で数字キーボードが出る**
`inputmode="numeric"` を指定しました。

**通信が切れたら画面に出る**
オフラインだと名簿が更新されませんが、これまで無表示でした。
上部に警告を出します。

**卓組みの間を追加した**

館の中の一室として、幹事用の画面を足しました。診断順に席が埋まる方式を
やめられます。あわせて、幹事が席を告げるまで結果を伏せておく
待機モードを用意しました。
あわせて、診断の直前に腕前と途中退出を聞く2問を足しました。
図鑑収集モードでは聞きません（席に関係しないため）。

**結果に卓の説明が付く**
「A卓（笑い声の宴の間）」だけでは、実際に何を遊ぶ卓なのかが伝わりません。
どんなゲームを、どんな雰囲気で遊ぶ卓かを1行で添えました。納得感が変わります。

**結果テキストをコピーできる**
全体に `user-select: none` がかかっていたため、
同卓メンバーの名前を選択できませんでした。結果欄だけ選択可にしています。

**キーボード操作でも現在位置が分かる**
フォーカス表示を追加しました。あわせて、視差やアニメーションを抑える設定を
OS側で有効にしている人には、点滅や走査線を止めるようにしています。

## 既知の課題（今後直すなら）

- `js/data.js` の `q_coop_deep2` と `q_coop_deep4` は、どこからも呼ばれない未使用の質問です。消すか、経路に組み込むか決める必要があります。
- 「次元跳躍の才」（神の座）で名簿に登録すると、その端末自身の記録を上書きします。制作者用の機能なので実害はありませんが、仕様として把握しておいてください。
- 遅刻者が後から診断した場合は、`kumi.html` で組み直しになります。すでに座っている人を「固定」してから組み直すと、必要な人だけが動きます。
- 卓ごとに遊ぶゲームを登録して、所要時間や人数と突き合わせる機能はまだありません。

## 音源について

`assets/audio/` の音源は配布元の利用規約に従ってください。
**このリポジトリは非公開（Private）で運用してください。**
公開すると音源の再配布にあたる可能性があるほか、
隠しコマンドや深淵クイズの答えがソースから読めてしまいます。
